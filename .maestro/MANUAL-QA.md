# 実機 QA チェックリスト（E2E で自動検証できない項目）

Maestro E2E（`.maestro/README.md`）は accessibility ラベル・テキスト表示の到達確認が中心であり、
以下は「実際に目で見て意味のある形で描画されているか」「実機固有の挙動が正しいか」を
確認する必要があるため、Maestro では検証できない。development build を実機（推奨）または
エミュレータにインストールして、1 項目ずつチェックすること。

各項目に「前提条件（無いと実行できないもの）」「操作手順」「期待値（何が見えれば OK か）」を記載する。
実装を読んで確認した内容のみを記載し、憶測は書いていない。不明点は「要確認」と明記する。

## 1. 2FA の QR コード表示（Android 実機での GIF data URI 描画）

対象: `components/settings/TwoFactorEnableSection.tsx`

**前提条件**: 特になし（サーバー API のみで完結。外部連携不要）

**操作手順**:
1. ログイン → プロフィールタブ →「設定を開く」→ 設定画面内の「2段階認証」セクションを開く
2. 「2段階認証を設定する」をタップする

**期待値**:
- [ ] タップ後、白背景の正方形（200×200pt）の中に**実際の QR コードの模様（白黒の格子状ドットパターン）**が表示される。単色の白い四角・グレーの塗りつぶし・崩れた画像アイコンではないこと
- [ ] QR コード画像の下に「シークレットキー」ラベルと英数字の値が表示される
- [ ] さらにその下に「otpauth URL」ラベルと `otpauth://totp/...` 形式の値が表示される
- [ ] （可能であれば）Google Authenticator 等の認証アプリで実際に QR コードを読み取り、6桁コードが生成されることを確認する。読み取れた場合は QR コードが正しくデコード可能であることの最終確認になる
- [ ] QR コードが表示されない・崩れている場合は「シークレットキー」のテキスト値からも認証アプリへ手動登録できることを確認する（フォールバック導線）

## 2. 盆栽園マップ（Leaflet を WebView で表示）

対象: `components/shops/BonsaiMapView.tsx`

**前提条件**: 位置情報許可はマップ表示そのものには不要（現在地ボタンでのみ使用）。ネットワーク接続必須（OSM タイル取得のため）

**操作手順**:
1. プロフィールタブ横の「その他」タブ →「盆栽園マップ」をタップ（`app/shops/index.tsx`）
2. 一覧画面の最上部に表示される地図領域を確認する

**期待値**:
- [ ] 「地図を読み込み中...」のローディング表示から、20秒以内に地図（OpenStreetMap のタイル + 緑色のピンマーカー）へ切り替わる。20秒経っても切り替わらない場合はタイムアウトのバグであり、「読み込みに失敗しました」表示＋再試行ボタンに切り替わることを確認する（このタイムアウト設計自体が正しく動くかも確認対象）
- [ ] タイムアウト・エラー時に画面下部へ `ERR_MAIN_FRAME` / `ERR_JS` / `ERR_TIMEOUT` のいずれかの診断コードが小さく表示されること（次回報告用の診断情報。これが出ない場合は実装側の表示ロジック不具合の可能性）
- [ ] 地図上の盆栽園ピンをタップ → ポップアップ（店名・住所・評価・「詳細を見る」リンク）が表示される
- [ ] ポップアップ内の「詳細を見る」をタップ → 店舗詳細画面（`/shops/[id]`）へ遷移する
- [ ] 右下の「現在地に移動」ボタンをタップ → 位置情報許可ダイアログが出る（初回）→ 許可すると地図が現在地付近へ移動する
- [ ] 地図領域を指でドラッグ・ピンチズームした際、外側のリスト（FlatList）がスクロールに割り込まず、地図内の操作として正しく処理されること（`nestedScrollEnabled` の実機確認）

1. 「その他」タブ →「植物ホルモン」→「相互作用ダイアグラム」をタップ（`app/hormones/diagram/index.tsx`）

## 4. 投稿カードの墨枠内写真表示

対象: `components/post/PostImageGallery.tsx`（墨筆枠は `assets/images/brush-frames/post-frame.svg` を `PostCard.tsx` が border-image 的に伸縮表示）

**前提条件**: 画像付きの投稿が最低数件フィードに表示されていること（1枚・2枚・3枚・4枚の投稿があれば理想）

**操作手順**:
1. フィードで画像1枚の投稿、画像2〜4枚の投稿をそれぞれ表示する
2. 画面回転・異なる端末幅（可能であれば複数機種）で確認する

**期待値**:
- [ ] 画像が**墨筆の枠線の内側に収まっている**こと。枠線からはみ出す・枠と画像の間に不自然な隙間や重なりがないこと（実装コメントに「実機報告の原因」と記載された過去の不具合＝画像が枠に重なる問題の再発がないかの確認）
- [ ] 画像1枚時は横長（16:9 相当）、2〜4枚時は正方形グリッドで、画像間に一定の溝（2pt 程度）があること
- [ ] 画像をタップ → フルスクリーンの画像ビューアが開くこと
- [ ] 投稿カードの高さが画像枚数に応じて可変でも、枠線が崩れない（枠線が伸び切って歪む・切れることがない）こと

## 8. Google 新規登録の規約同意モーダル（403 → 同意 → 再送）

**前提条件**: **Google OAuth 環境変数（`EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` / `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`）が設定されたビルドが必要**。また、Bon_Log に**未登録**の Google アカウント（実機の Google アカウント選択で選べるテスト用アカウント）が必要（既存ユーザーでは 403 が発生しないため検証できない）

**操作手順**:
1. ログイン画面または新規登録画面で「Google でログイン」を実行する
2. Bon_Log に未登録の Google アカウントを選択する

**期待値**:
- [ ] ネイティブの Google アカウント選択 UI が表示され、アカウントを選ぶと、アプリ内に「利用規約への同意」モーダルが表示される（403 `TERMS_ACCEPTANCE_REQUIRED` を検知した結果）
- [ ] モーダル内の同意チェックボックスが未チェックの状態で開始する（前回操作の状態が残っていないこと）
- [ ] チェックせずに「同意して続行」をタップ → ボタンが無効化されており押せない（グレーアウト表示）こと
- [ ] チェックを入れて「同意して続行」をタップ → **ネイティブのアカウント選択が再表示されずに**（直前の ID トークンを再利用）、そのままアカウント作成が完了しフィード画面へ遷移する
- [ ] 「キャンセル」をタップ → モーダルが閉じ、ログイン/登録前の画面に戻る（アカウントは作成されない）
- [ ] 同じ未登録 Google アカウントで再度試行し、同意モーダルが正しく毎回リセットされること

## 9. 大文字スキーム URL のリンク（`HTTPS://example.com` タップでブラウザが開く）

対象: `lib/utils/normalize-url-scheme.ts` の適用箇所（`app/shops/[id]/index.tsx` の `handleOpenWebsite`、`app/events/[id]/index.tsx` の `handleOpenExternalUrl`）

**背景（実装コメントより）**: サーバーは `/^https?:\/\//i` で大文字小文字を区別せず URL を受理するため `HTTPS://example.com` のような値が保存され得るが、Android の `expo-web-browser`（`WebBrowserModule.kt`）の IntentFilter 照合は大文字小文字を区別する。以前はこの不一致により**タップしても何も起きない（サイレント失敗）**という実害のある不具合があり、`normalizeUrlScheme()` で対処済みとされている（`docs/handoff-to-codex-2026-07-14.md` §12）。**Android 実機での動作確認は未実施のまま残っている**。

**前提条件**: 盆栽園の Web サイト URL を**大文字スキームで**登録できる状態が必要。ネイティブアプリの盆栽園編集画面（`app/shops/new/index.tsx` または `app/shops/[id]/edit/index.tsx`）の「Web サイト URL（任意）」欄から `HTTPS://example.com` のように**スキームを大文字で**入力して登録する（自分が作成・編集できる盆栽園データが必要）

**操作手順**:
1. 上記の方法で `website` が `HTTPS://example.com`（または任意の大文字スキーム URL）の盆栽園データを用意する
2. その盆栽園の詳細画面（`/shops/[id]`）を開く
3. 「公式サイトを開く（外部リンク）」の行をタップする

**期待値**:
- [ ] タップ後、エラーなく Chrome カスタムタブ（`expo-web-browser`）が開き、登録した URL のページが表示される
- [ ] 何も起きない（サイレント失敗）・アプリがクラッシュする・Sentry にのみエラーが飛んで画面上は無反応、のいずれにもならないこと
- [ ] イベント詳細画面の外部リンク（`externalUrl`）でも同様に確認する（`app/events/[id]/index.tsx`）

## 10. Push 通知（受信・タップでの画面遷移）

対象: `lib/push/`（`notification-setup.ts` / `notification-routing.ts` / `notification-navigation.ts` / `device-registration.ts`）

**前提条件（これが無いと実行できない）**:
- [ ] **`android/app/google-services.json` が配置され、`app.json` の `expo.android.googleServicesFile` が設定されたビルドが必要**。2026-07-29 時点でこのファイルは存在せず、`docs/handoff-to-codex-2026-07-14.md` §10.1 により「FCM standalone Push は未完成」と記録されている。**この前提が満たされない限り本項目は実行不可**（app.json 変更は本ドキュメント整備タスクの担当範囲外。frontend/core への差し戻しが必要）
- [ ] サーバー（Bon_Log_cfw）側でこのテストアカウント宛に Push を発火させる手段（いいね・コメント等を実際に発生させる、または開発環境の通知送信ツール）が必要

**操作手順**:
1. ログイン後、通知が価値を持つ操作（例: 誰かにフォローされる、投稿にいいねされる）が発生する文脈まで進める
2. OS の通知許可ダイアログが表示されたら許可する
3. アプリをバックグラウンドにした状態で、別アカウントから対象アカウントの投稿にいいね・コメントする
4. 端末の通知シェードに通知が届いたらタップする

**期待値**:
- [ ] 通知許可ダイアログは初回起動直後ではなく、上記のような文脈がある操作の後に表示される（`push-notifications.md` の方針通り）
- [ ] バックグラウンド時にいいね・コメント等を受けると、Android の通知シェードに通知が表示される（アイコン・タイトル・本文が表示される。§10.1 に「Bon_Log 専用の小型通知アイコンが無い」と記録されているため、Expo 標準アイコンのままになっていないか確認する）
- [ ] 通知をタップ → アプリが起動（またはフォアグラウンド化）し、**該当する投稿の詳細画面**へ遷移する（like/comment/reply/comment_like/quote/repost/mention 通知の場合）
- [ ] フォロー通知をタップ → 対象ユーザーのプロフィール画面へ遷移する
- [ ] フォローリクエスト通知をタップ → フォローリクエスト一覧へ遷移する
- [ ] アプリがフォアグラウンドの状態で通知を受信した場合、バナー表示されること（`shouldShowBanner: true` の設定通りか）
- [ ] ログアウト操作を行うと、以後そのデバイスへの Push が届かなくなること（デバイストークン登録解除の確認。`auth-tokens.md` のログアウト手順との整合）

## 11. 課金（Play サンドボックスでの購入 → Webhook → プレミアム解放）

対象: `lib/billing/purchases.ts`、`app/settings/subscription/index.tsx`

**前提条件（これが無いと実行できない）**:
- [ ] `.env.local` に `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` が設定されていること（未設定の場合 `initBilling()` は no-op になり、SDK が初期化されずテスト不能）
- [ ] RevenueCat ダッシュボードで Android（Play Billing）が接続され、Offering・Package が設定済みであること
- [ ] Google Play Console 側でサブスクリプション商品（product / base plan）が設定され、**ライセンステスター**としてテスト用 Google アカウントが登録されていること
- [ ] production/preview の署名でビルドされた AAB/APK が Play の内部テストトラック等にアップロードされていること（Play サンドボックス課金はデバッグ署名では動作しないことが多い — 要確認。Google Play の課金テストに関する公式ドキュメントで最新要件を確認すること）
- [ ] cfw 側の RevenueCat Webhook 設定・provider 別 entitlement 判定が本番相当で動作していること（`docs/handoff-to-codex-2026-07-14.md` §11.6・§13.1 の cfw 対応状況を参照）

**操作手順**:
1. ライセンステスター登録済みのテストアカウントでログインする
2. プロフィール →「設定を開く」→ サブスクリプション設定画面（`app/settings/subscription/index.tsx`）を開く
3. 「プレミアムプランを購入する」をタップし、Play の購入フローを完了する（テスト決済のため実際の課金は発生しない）

**期待値**:
- [ ] 価格表示が RevenueCat の Offering から取得した実際の価格文字列になっている（ハードコードされた固定値ではない）こと
- [ ] 購入完了後、「反映には数秒かかることがあります」という案内が表示され、その後サーバー側の購読状態（`users.me` の `isPremium`）が invalidate されてプレミアム機能が解放されること
- [ ] 購入フロー中にユーザーがキャンセルした場合、エラー扱いにならず静かに購入前の状態へ戻ること
- [ ] 保留（pending）状態になった場合、案内メッセージが表示されること
- [ ] 「購入を復元する」ボタンをタップ → 過去の購入がある場合に正しく復元され、プレミアム状態が反映されること（審査要件）
- [ ] 「Google Play の定期購入を管理する」導線をタップ → Play の購読管理画面へ遷移すること（アプリ内に Stripe 等の外部決済導線が一切無いことも合わせて確認する。`.claude/rules/store-compliance.md`）
- [ ] 解約（Play 側でサブスクリプションをキャンセル）後、期限到来でプレミアム機能が正しく失効すること（時間がかかるため即時確認できない場合はテスト用の短期間サブスクリプションプランでの検証を検討する）
